# project-analysis

面向加密项目的证据优先分析 Skill，适用于 Codex。

它不是项目介绍模板，而是一套可执行的尽调流程：

- 先验证项目是否真实运行，再分析经济模型。
- 区分充值、成交量、协议收入、代币增发和账面奖励。
- 用当前边际条件计算单位成本，不沿用旧报告的平均值。
- 对算力、矿机、节点、NFT 分红等份额制项目做稀释压力测试。
- 用早期、晚期和盈利案例校验机制，而不是只挑成功故事。
- 明确退出路径、合约权限、未验证项和反证条件。
- 输出“可做 / 小仓验证 / 只研究 / 不参与”的分级结论。

## 安装

把本目录复制到 Codex 的 skills 目录：

```text
%USERPROFILE%\.codex\skills\project-analysis
```

目录结构应保持为：

```text
project-analysis/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── analysis-method.md
    └── report-template.md
```

安装后可使用：

```text
$project-analysis
```

也可以直接描述任务，例如：

```text
分析这个项目：<链接、合约地址或旧调研>
```

## 适用场景

- 项目链接、官网、白皮书、文档。
- 合约地址、链上状态、协议 API。
- DeFi、GameFi、算力挖矿、节点、NFT 分红。
- 收益截图、交易记录、排行榜账户。
- 旧调研复核。

## 不适用场景

- 纯价格预测。
- 没有可验证材料的“听说很赚钱”。
- 代替审计、法律意见或投资建议。

## 分析原则

1. 先证明项目在运行。
2. 再证明钱真的能收到。
3. 最后才讨论收益有多高。

报告必须带时间戳、链/区块和数据源。无法验证的内容必须标记为“未验证”。

## 案例校准

`references/analysis-method.md` 包含两个案例，用于校准判断：

- Papertrade：旧发行公式失效后，单位成本从约 15.69 升到 158.40 USDC / 万枚，代币不可转让，不能按市值估值。
- Computers RH：算力份额会被新增设备持续稀释，奖励池主要由新资金注资，不能把当前单机日收益当固定回本。

## 安全边界

本 Skill 只做分析和报告生成，不连接钱包、不签名、不提交交易。
